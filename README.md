## 一句话

样例「改期意图」→ Agent/规则解析出改期提案卡 → 用户确认 / 修改 / 拒绝 → 写入本地日程状态 → 结果核验；可演示拒绝与过期失败态。

## 快速打开

### 方式 A：静态服务器（推荐）

```bash
cd gosim-intent-cabin
python3 -m http.server 8877
# 浏览器打开 http://127.0.0.1:8877/
# （若端口占用，换任意空闲端口即可）
```

### 方式 B：直接打开

用浏览器打开本目录下的 `index.html`。  
若 `file://` 无法 `fetch` `data/schedule.json`，脚本会自动使用内嵌兜底练习数据，闭环仍可走通。

## 演示脚本（约 2 分钟）

### 快乐路径

1. 打开页面，左侧可见教练改期消息；右侧为练习训练日程。  
2. 点 **「解析意图 → 生成提案卡」**。  
3. 查看旧/新时间对比；若教练原时段冲突，Agent 会自动建议避让时段。  
4. （可选）修改日期/时间 → **应用修改到提案**。  
5. 点 **「确认授权 · 写入日程」**。  
6. 右侧日程高亮已改期事件；「结果核验」显示成功；审计日志有写入记录。

### 失败态 A：拒绝授权

1. **重置 Demo** → 再次生成提案。  
2. 点 **「拒绝」**。  
3. 核验区显示失败；日程不变。

### 失败态 B：提案过期

1. **重置 Demo** → 生成提案。  
2. 点 **「强制过期」**（或等待约 90 秒）。  
3. 核验区显示过期失败；无法再确认写入。

### 失败态 C：写入冲突（可选）

1. 生成提案后，把新时间改到与已有课重叠（例如改到周三 18:30–19:45）。  
2. 应用修改 → 确认。  
3. 核验区提示冲突，未写入。

## 练习数据 vs 真日历

| | 本 Demo | 晋级后 / 真接入 |

| 输入 | 写死样例消息 | robrix2 / 邮件 / 消息能力 |

| 日程 | `data/schedule.json` + localStorage | 系统日历读改 API |
